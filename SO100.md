# mimic-video on the SO-100 / SO-ARM100

This document describes the changes made to run **mimic-video** (Video-Action Models) on the
**SO-100** — a low-cost 6-DoF arm with Feetech servos — which is **not** one of the robots the
upstream repo ships configs for (it targets Franka / WidowX / bimanual setups).

The approach: treat the frozen **Cosmos-Predict2** video backbone as a general prior and train a
small **SO-100 action decoder** on top, using the repo's existing world→action pipeline, then
deploy closed-loop on the real arm.

> **Update (2026-09-29):** `so100/process_so100_v3.py` has been rewritten for multi-camera, N-DoF data. It now writes
> **safetensors** episodes, which is the format the dataloader actually reads, instead of zarr. See
> [SO101.md](SO101.md) for the current v3.0 pipeline. The v3.0 steps below describe the original zarr-based version.

---

## TL;DR — end-to-end pipeline

```
record SO-100 demos (LeRobot v2.1 or v3.0)
   │   process_so100.py            (v2.x: per-episode parquet+mp4)
   │   so100/process_so100_v3.py   (v3.0: chunked parquet + concatenated video, via LeRobotDataset)
   ▼
per-episode .zarr  (workspace_rgb JPEG @10Hz, joint_state/joint_action lowdim @30Hz, language)
   │   precompute_t5.py            (adds language_embedding)
   ▼
fine-tune action decoder from a pretrained checkpoint  (configs/dataloading/so100*.yaml)
   ▼
deploy closed-loop on the real arm
   so100/so100_policy_server.py    (mimic-video env: model → joint-chunk over a socket)
   so100/so100_robot_client.py     (lerobot env: camera+joints → server → motor commands)
```

The two deploy scripts run in **separate environments on purpose** — the policy needs
`torch 2.7.1+cu128` (+ ABI-pinned transformer-engine/flash-attn/apex), while current lerobot needs
`torch ≥ 2.10`. They communicate over a localhost socket.

---

## SO-100 specifics
- **Action/observation space:** 6 joints (`shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper`), **absolute** joint angles in degrees — not end-effector poses, so none of the upstream pose/rotation transforms are used.
- **Single fixed third-person camera** mapped to `workspace_rgb`.
- **Calibration matters:** the decoder learns the arm's *absolute* joint frame, so the deployment arm must be in the **same calibration** the training data was recorded with (re-calibrating after recording breaks deployment).

## Files ADDED

| File | Purpose |
|---|---|
| `data_preprocessing/action/process_so100.py` | Convert a **LeRobot v2.0/v2.1** SO-100 dataset → mimic zarr. Picks one fixed third-person camera (excludes wrist cams), stores frames as JPEG subsampled to 10 Hz, joints at full 30 Hz, language. Handles heterogeneous datasets (auto camera pick, 6-DoF filter, integer-or-string task labels). |
| `so100/process_so100_v3.py` | Same output, for the **LeRobot v3.0** format (chunked parquet + concatenated per-chunk video). Reads via `LeRobotDataset` so the v3.0 layout + video decoding are handled by lerobot. |
| `model/cosmos_predict2/configs/dataloading/dataset/so100.yaml` | Dataset config: declares the SO-100 data components (`workspace_rgb`, `joint_state_lowdim`, `joint_action_lowdim`, language) and the `MimicDataset`. |
| `model/cosmos_predict2/configs/dataloading/policy_io/so100.yaml` | Policy I/O: obs = 5 frames @5Hz + current 6 joints + language; action = 56-frame video plan + **15-step absolute 6-joint** chunk (VARIANCE-normalized). |
| `model/cosmos_predict2/configs/dataloading/dataset/transform/so100_to_so100.yaml` | Transforms: resize image to 480×640, flatten + concat the 6-joint lowdim. Drops the bridge/libero pose/rotation transforms (SO-100 is joint-space). |
| `model/cosmos_predict2/configs/dataloading/so100.yaml` | Top-level data_config wiring `dataset: so100` + `policy_io: so100`. |
| `…/so100_real.yaml`, `…/so100_ft2.yaml`, `…/so100_ft3.yaml` (+ matching `dataset/*.yaml`) | Per-dataset instances (same as `so100.yaml` with a different `data_dir` / `num_val_episodes`). Copy `so100.yaml` and point `data_dir` at your converted zarr to make a new one. |
| `so100/so100_policy_server.py` | **Policy server** (mimic-video env). Loads the fine-tuned decoder + frozen backbone + normalizer + a fixed language embedding; keeps a 5-frame obs buffer; serves `predict(frame, joints) → (15,6)` absolute joint targets over a socket. `nstep` (video denoising steps) is a per-request knob for speed. |
| `so100/so100_robot_client.py` | **Robot client** (lerobot env). Reads the fixed camera + 6 joints via `SOFollower`, calls the server, executes the first few predicted joint targets (with a per-command `--max-rel` safety cap), re-observes. Supports `--dry-run` (no motion). Resilient to transient Feetech bus glitches. |
| `SO100.md` | This document. |

## Environment notes (RTX 5090 / sm_120)
- The policy stack is pinned to **torch 2.7.1+cu128** with **`transformer-engine 1.13.0+cu128.torch271`, `flash-attn 2.6.3+cu128.torch271`, `apex 0.1+cu128.torch271`** (NVIDIA cosmos dependency index `cu128_torch271`). These compiled extensions are ABI-locked to torch 2.7.1.
- **flash-attn 2.6.3 lacks sm_120 kernels**, so the SO-100 decoder uses `atten_backend="torch"` (PyTorch SDPA) instead of `flash_attn_no_cp`. The decoder is small, so there's no meaningful speed loss.
- Deployment is **two processes** (policy server + robot client) because the model and lerobot require incompatible torch versions.

## Quick start
```bash
# 1. convert  (v3.0 shown; use process_so100.py for v2.x)
#    edit REPO/OUT/SAFE at the top of so100/process_so100_v3.py
python so100/process_so100_v3.py

# 2. language embeddings
python data_preprocessing/action/precompute_t5.py --dataset-path /path/to/so100_zarr

# 3. make a data config: copy configs/dataloading/so100.yaml + dataset/so100.yaml,
#    point data_dir at your zarr  (e.g. so100_mine)

# 4. fine-tune the decoder from a pretrained checkpoint
torchrun --nproc_per_node=1 -m scripts.train --config=cosmos_predict2/configs/config.py -- \
  experiment=w2a_so100_mine_v2w_pretrained_cosmos_lr1.000e-04_layer20_bsz1 \
  job.name=so100_mine model.config.action_dit_path=/path/to/pretrained.pt \
  optimizer.lr=2e-5 trainer.grad_accum_iter=32 trainer.max_iter=150

# 5. deploy (two terminals / two envs)
python so100/so100_policy_server.py                     # mimic-video env (GPU)
python so100/so100_robot_client.py --dry-run            # lerobot env  (then drop --dry-run)
```
> The deploy scripts contain hard-coded paths (checkpoint, stats cache, dataset repo) — edit the constants at the top of each for your setup.
