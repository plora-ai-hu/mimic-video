# SO-101: multiple cameras and one or two arms

This extends the [SO-100 support](SO100.md) to LeRobot v3.0 datasets with several camera views and any number of joints. The goal is a dual SO-101 setup with a workspace camera and one camera on each wrist. Until that dataset exists, the pipeline is exercised on the single-arm cabling demo in `/scratch/nk_plora/cabling_demo_dataset`: 165 episodes at 15 fps, with a `top` and a `wrist` camera at 640x480, 6 joints, and an empty task string.

Deployment uses a policy server on a GPU node and a robot client on the machine with the arm (see [Deployment](#deployment)). The two-arm configs are in place but untested, and the client drives only a single arm so far.

## Camera views: tiled into one frame

The video backbone and the action decoder take a single 480x640 stream (`workspace_rgb`). Each view is resized to 240x320 and placed in a fixed 2x2 grid:

```
+-----------------+-----------------+
|    scene_rgb    |     (black)     |
+-----------------+-----------------+
| left_wrist_rgb  | right_wrist_rgb |
+-----------------+-----------------+
```

Missing views stay black. The single-arm cabling data fills `scene_rgb` (top camera) and `right_wrist_rgb` (wrist camera). Because one- and two-arm data share this layout, a video backbone finetuned on one can be used for the other.

The layout is implemented once, in [tiling.py](model/cosmos_predict2/data/action/tiling.py), and used in two places:
- the `TileViews` transform of the action dataloader;
- the video-dataset builder;
- the policy server.

## Data layout

| Step | Output |
| --- | --- |
| Converter ([so100/process_so100_v3.py](so100/process_so100_v3.py)) | `episodes/episode_XXXXXX.safetensors`:<br>- one `(T, 240, 320, 3)` uint8 array per view at 5 Hz;<br>- `joint_state_lowdim` / `joint_action_lowdim` as `(T, D)` float32 at the dataset rate, with D = 6 for one arm and 12 for two;<br>- `language_instruction`;<br>- a `<key>_timestamps` array (ns) for every key.<br>Joint names and view mapping go in the safetensors metadata. |
| [precompute_t5.py](data_preprocessing/action/precompute_t5.py) | adds `language_embedding` to the episodes (action decoder data) |
| [process_so101_video.py](data_preprocessing/video/process_so101_video.py) | `video_dataset/video/*.mp4` (tiled 480x640 at 5 fps) and `video_dataset/metas/*.txt` |
| [precompute_t5_embeddings.py](data_preprocessing/video/precompute_t5_embeddings.py) | `video_dataset/language_embeddings/*.safetensors` (video backbone data) |

The converted cabling data lives in `/scratch/nk_plora/mimic/so101_cabling/{episodes,video_dataset}`, which is where the configs below point.

| Transforms (`TileViews`) | [so101_to_so101_1arm.yaml](model/cosmos_predict2/configs/dataloading/dataset/transform/so101_to_so101_1arm.yaml) | [so101_to_so101_2arm.yaml](model/cosmos_predict2/configs/dataloading/dataset/transform/so101_to_so101_2arm.yaml) |
| Action decoder net | `so101_1arm` (6 in, 6 out) in [world2action_pipe.py](model/cosmos_predict2/configs/defaults/world2action_pipe.py) | `so101_2arm` (12 in, 12 out) |
| Video dataset | `so101_1arm_cabling` in [data_video.py](model/cosmos_predict2/configs/defaults/data_video.py) | `so101_2arm` |

Action decoder experiments pick their net by data-config prefix: `so101_1arm*` uses `so101_1arm`, and `so101_2arm*` uses `so101_2arm`. To add a new dataset, copy the dataset yaml and the top-level yaml, keeping that prefix, and add a `data_video.py` entry.

Timing matches the SO-100 setup:
- The video model sees 5 observed and 56 predicted frames at 5 Hz.
- The action decoder gets 1 state and predicts 15 absolute joint targets at 5 Hz (3 s).

## Pipeline

Run everything from the repository root on compute nodes; don't run it on the login node. Use `--ntasks=1` so `srun` doesn't start the script twice.

```bash
# 1. LeRobot v3.0 -> safetensors episodes (lerobot image; about 4 min for the cabling demo on 32 CPUs)
srun --account=nk_plora --partition=cpu --ntasks=1 --cpus-per-task=32 --mem-per-cpu=4000 --time=02:00:00 \
  singularity exec -B /project -B /scratch/nk_plora /project/nk_plora/lerobot_train.sif \
  python so100/process_so100_v3.py \
    --root /scratch/nk_plora/cabling_demo_dataset \
    --out /scratch/nk_plora/mimic/so101_cabling/episodes \
    --view observation.images.top=scene_rgb \
    --view observation.images.wrist=right_wrist_rgb \
    --prompt "route the cable" --num-workers 24
# Two arms: --view <workspace>=scene_rgb --view <left wrist>=left_wrist_rgb --view <right wrist>=right_wrist_rgb

# 2. Tiled videos for backbone finetuning (mimic-video image, CPU)
srun --account=nk_plora --partition=cpu --ntasks=1 --cpus-per-task=16 --mem-per-cpu=4000 --time=01:00:00 \
  singularity exec -B /project -B /scratch/nk_plora /project/nk_plora/mimic-video.sif bash -c "cd model && \
  PYTHONPATH=. python ../data_preprocessing/video/process_so101_video.py \
    --episodes /scratch/nk_plora/mimic/so101_cabling/episodes \
    --out /scratch/nk_plora/mimic/so101_cabling/video_dataset --num-workers 16"

# 3. T5 language embeddings for both datasets (GPU; needs model/checkpoints/text_encoder)
srun --account=nk_plora --partition=gpu --ntasks=1 --gres=gpu:1 --cpus-per-task=16 --time=01:00:00 \
  singularity exec --nv -B /project -B /scratch/nk_plora /project/nk_plora/mimic-video.sif bash -c "cd model && \
  PYTHONPATH=. python ../data_preprocessing/action/precompute_t5.py --dataset-path /scratch/nk_plora/mimic/so101_cabling/episodes && \
  PYTHONPATH=. python ../data_preprocessing/video/precompute_t5_embeddings.py --dataset-path /scratch/nk_plora/mimic/so101_cabling/video_dataset"
```

Checkpoints: the T5 encoder, VAE tokenizer and `v2w_pretrained_cosmos.pt` (~47 GB) are in `/project/nk_plora/mimic-video-checkpoints`. `model/checkpoints` must be a symlink to that directory, since the home quota is too small for them:

```bash
ln -sfn /project/nk_plora/mimic-video-checkpoints model/checkpoints
```

## Training

Training runs through [container/train.sbatch](container/train.sbatch). `EXPERIMENT` selects the experiment, and any extra arguments are passed on as config overrides. Outputs go to `/project/nk_plora/outputs/mimic-video/<project>/<group>/<job name>/`.

```bash
# Weights & Biases (once): WANDB_API_KEY, optional WANDB_ENTITY / WANDB_PROJECT / WANDB_MODE
cp secrets.env.example secrets.env && chmod 600 secrets.env && $EDITOR secrets.env

# 4. Video backbone: LoRA finetune of Cosmos-Predict2 2B on the tiled videos (global batch 4 over 4 GPUs)
EXPERIMENT=v2w_so101_1arm_cabling_lora_rank256_lr1.778e-04_bsz4 \
  sbatch --gres=gpu:4 container/train.sbatch trainer.max_iter=10000 checkpoint.save_iter=1000 \
  model.config.pipe_config.net.sac_config.mode=block_wise

# 5. Action decoder on top of the frozen, finetuned backbone
EXPERIMENT=w2a_so101_1arm_cabling_v2w_pretrained_cosmos_lr1.000e-04_layer20_bsz4 \
  sbatch --gres=gpu:4 container/train.sbatch \
  model.config.video_dit_path=/project/nk_plora/outputs/mimic-video/posttraining/video2world/v2w_so101_1arm_cabling_lora_rank256_lr1.778e-04_bsz4/checkpoints/model/iter_000010000_fused.pt
```

**Fused checkpoints.** Every saved video backbone checkpoint `iter_XXXXXXXXX.pt` gets a fused copy `iter_XXXXXXXXX_fused.pt` next to it; `VideoEvalCallback` merges the LoRA weights into the base model, which takes about 30 s. That fused copy is what `video_dit_path` expects. To fuse a checkpoint by hand:

```bash
singularity exec -B /project /project/nk_plora/mimic-video.sif python model/scripts/fuse_lora_ckpt.py <iter_XXXXXXXXX.pt>
```

Leaving out `video_dit_path` trains the decoder on the un-finetuned Cosmos backbone. Normalization statistics are computed on the first action run and cached in `<data_dir>/.statistics_cache/`.

**GPU memory.** On the A100-40GB nodes, the video backbone runs out of memory with the default selective activation checkpointing (`predict2_2b_720`) at 61x480x640. Pass `model.config.pipe_config.net.sac_config.mode=block_wise`, which checkpoints whole blocks and uses a peak of about 18 GB at batch size 1 per GPU. The action decoder fits without changes.

**Smoke tests** run on one GPU of the `test` partition (1 h limit) at batch size 1:

```bash
EXPERIMENT=v2w_so101_1arm_cabling_lora_rank256_lr1.778e-04_bsz1 sbatch --partition=test --gres=gpu:1 --cpus-per-task=16 --time=01:00:00 \
  container/train.sbatch trainer.max_iter=20 trainer.logging_iter=5 checkpoint.save_iter=20 trainer.validation_iter=10 trainer.max_val_iter=2 \
  job.name=smoke_v2w_so101_1arm_cabling model.config.pipe_config.net.sac_config.mode=block_wise
EXPERIMENT=w2a_so101_1arm_cabling_v2w_pretrained_cosmos_lr1.000e-04_layer20_bsz1 sbatch --partition=test --gres=gpu:1 --cpus-per-task=16 --time=01:00:00 \
  container/train.sbatch trainer.max_iter=20 trainer.logging_iter=5 checkpoint.save_iter=20 trainer.validation_iter=10 trainer.max_val_iter=2 \
  job.name=smoke_w2a_so101_1arm_cabling model.config.video_dit_path=<fused backbone checkpoint>
```

Measured on one A100-40GB:

| Stage | Time per training step |
| --- | --- |
| Video backbone | about 4.8 s |
| Action decoder | about 1.8 s |

Validation of the action decoder samples the backbone and takes a few minutes per pass.

**cuDNN on the current image.** `/project/nk_plora/mimic-video.sif` loads two copies of cuDNN, and every convolution fails with `ptrDesc->finalize()`. The cause is explained in [container/mimic-video.def](container/mimic-video.def), which now contains the fix for future builds. Until the image is rebuilt, `container/train.sbatch` works around it at runtime. Other GPU entry points that use the VAE need the same workaround; see `CUDNN_COMPAT` in the sbatch script.

The wandb callback takes `WANDB_ENTITY`, `WANDB_PROJECT` and `WANDB_MODE` from the environment in place of the configured values. `secrets.env` is gitignored; keep it at mode 600 and never commit it.

## Deployment

The policy server ([so101_policy_server.py](so100/so101_policy_server.py)) runs in the container on a GPU node. The robot client ([so101_robot_client.py](so100/so101_robot_client.py)) runs on the machine with the arm, in a LeRobot environment. They talk over an SSH tunnel with the protocol in [so101_protocol.py](so100/so101_protocol.py), which uses a JSON header and JPEG frames. The SO-100 scripts in `so100/` are the older single-camera version and are left unchanged.

```
laptop (LeRobot env)                                 compute node (mimic-video.sif, 1 GPU)
so101_robot_client.py -- ssh -L 8766, -J login --> so101_policy_server.py on 127.0.0.1:8766
  SO follower + OpenCV cameras                       fused backbone + action decoder + normalizer
  5-frame history per camera at 5 Hz                 tile_views, backbone up to --stop-step, decoder
```

What the server does:
- It loads the fused backbone, the decoder checkpoint and the normalization statistics. The statistics default to the single file in `<data_dir>/.statistics_cache/`.
- It takes the prompt embedding, prompt and joint names from the first episode (override with `--episode`). T5 is not loaded.
- Per query, it tiles the views exactly like training, runs the backbone up to denoising step `--stop-step` (default 0, a single forward pass) and returns 15 absolute joint targets in degrees. The first target is for 0.2 s after the newest frame.
- Every connection must present the token `MIMIC_POLICY_TOKEN`. Other users can reach 127.0.0.1 on a shared node, so the token is required.

**1. Token (once).** Put a random `MIMIC_POLICY_TOKEN` into `secrets.env`, for example from `openssl rand -hex 32`. Set the same value on the laptop.

**2. Server.** From the repository root:

```bash
EXPERIMENT=w2a_so101_1arm_cabling_v2w_pretrained_cosmos_lr1.000e-04_layer20_bsz4 \
VIDEO_DIT=<fused backbone, the decoder run's video_dit_path> \
DECODER=/project/nk_plora/outputs/mimic-video/vam/so101_1arm/<job name>/checkpoints/model/iter_XXXXXXXXX.pt \
  sbatch so100/so101_serve.sbatch [--stop-step N] [--debug-dir <dir>]
```

The log (`/project/nk_plora/logs/so101_policy_server-<job id>.out`) prints the tunnel command once the server is listening. `--debug-dir` saves the tiled input of every query as PNG.

**3. Tunnel.** On the laptop, keep this open while the job runs:

```bash
ssh -N -L 8766:localhost:8766 -J <user>@<login node> <compute node>
```

**4. Client.** In the LeRobot environment on the laptop, with a checkout of this repository (the client needs only `so100/so101_protocol.py` next to it):

```bash
export MIMIC_POLICY_TOKEN=...
# Offline check without the robot: replays a converted episode and prints the error against the recorded actions.
python so100/so101_robot_client.py --replay episode_000000.safetensors --cycles 10
# Robot, first without motion, then for real.
python so100/so101_robot_client.py --port /dev/ttyACM0 --cal-id <calibration id> \
  --camera top=/dev/video0 --camera wrist=/dev/video2 \
  --view top=scene_rgb --view wrist=right_wrist_rgb --rotate top=180 --dry-run
python so100/so101_robot_client.py ... --exec-steps 3 --max-rel 5
```

The cameras must match the training data:
- Same mounting and 640x480 resolution. `--rotate NAME=DEGREES` (90, 180, -90) rotates a camera's frames to match; the top camera currently needs `--rotate top=180`.
- `--view` uses the view names given to the converter.

The client checks the robot's joint names and the view names against the server before it starts. The control loop is synchronous at 5 Hz:
1. Each tick records the joints and all cameras.
2. The client sends a query and keeps recording while the arm holds still.
3. It sends the first `--exec-steps` targets, one per tick. `--max-rel` limits each joint change per command.
